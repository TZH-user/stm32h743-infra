# 串口控制命令说明

## 端口与接收方式

- 端口：现有 `USART1`，`PA9/TX`、`PA10/RX`。
- 串口参数：沿用工程当前配置 `8,000,000 baud`、`8N1`、无硬件流控。
- 接收：`DMA1_Stream2 + UART IDLE`，DMA Normal 模式。
- RTOS 对象：CubeMX 配置并生成 `SerialRxSem` 和独立的 `SerialControlTask`。
- 命令编码：ASCII，不区分大小写，以 `CR`、`LF` 或 `CRLF` 结束。
- 单行上限：127 个可见字符；超长行会丢弃到下一个换行符。

接收使用两个 256 字节 DMA 缓冲。UART IDLE/DMA 回调封存当前缓冲、立即尝试切换到空闲缓冲，并释放二值信号量 `SerialRxSem`；`SerialControlTask` 获得信号量后扫描全部就绪缓冲，负责组行和解析。二值信号量允许多个中断事件合并，因为任务每次都会扫描两个缓冲。UI 命令再进入 `UiControlQueue`，最后由 `DisplayTask` 执行 LVGL 页面或按钮事件。

## 命令

```text
PING
HELP
STATUS
RTOS
OUTPUT
OUTPUT LOG
OUTPUT OFF
OUTPUT ADC
OUTPUT FFT
UI STATUS
UI TAP RUN
UI TAP STOP
UI TAP PHASE+
UI TAP PHASE-
UI TAP CALSTART
UI TAP CALSTOP
UI PAGE MONITOR
UI PAGE SPECTRUM
UI PAGE TEST
UI PAGE CALIBRATION
UI PAGE SYSTEM
CAL STATUS
CAL START
CAL STOP
```

`UI TAP` 会在当前活动页面查找对应控件，并发送与触摸点击相同的 `LV_EVENT_CLICKED`。当控件不在当前页面或处于禁用状态时，命令返回 `ERR`。`UI PAGE` 复用现有页面创建和加载接口。

`UI PAGE RESULTS` 作为旧上位机脚本兼容别名继续保留，当前等价于 `UI PAGE CALIBRATION`；新脚本应使用 `UI PAGE TEST` 或 `UI PAGE CALIBRATION`。

`CAL START/STOP` 是 `UI TAP CALSTART/CALSTOP` 的便捷别名，仍通过 UI 队列在 DisplayTask 中执行。`CAL STATUS` 额外输出逐步逼近状态、最后 ADC 统计、PC6/PC7 ODR、DAC DOR1 和 AD9226 running。

## 输出模式约束

USART1 同时承担现有 VCP/VOFA 输出。为了避免文本响应破坏 ADC/FFT 数据流：

- `HELP`、`STATUS`、`RTOS` 和 UI 执行结果只在 `OUTPUT LOG` 模式输出文本。
- 在波形模式下需要查询时，先发送 `OUTPUT LOG`，等待 `[CTRL] OK OUTPUT log`，再发送查询命令。
- `OUTPUT ADC` 或 `OUTPUT FFT` 会恢复现有波形输出模式。
- UI 命令在非 LOG 模式仍会执行，但不会向波形流插入确认文本。

## 状态查询范围

- `STATUS`：系统 tick、MainTask、PhaseLockTask、输出模式、校准状态、RX 统计和 UI 命令统计。
- `RTOS`：任务数、FreeRTOS heap、既有任务栈水位和 VCP 队列统计。
- `UI STATUS`：UI 命令入队、执行、拒绝、丢弃和最近一次结果。

- `.map` 已确认双 RX DMA 缓冲 `s_rx_dma_buffers` 位于 RAM_D2 `0x30020000`，总大小 `0x200`。
- 链接结果仅保留业务模块的 strong `StartSerialControlTask`，CubeMX 生成的 weak 空实现未进入最终固件。
- 本次“DMA/IDLE 中断释放信号量 + 独立任务”版本尚未烧录，不能据此宣称接收可靠性已通过实机验收。

- 此前消息队列版本在 8 Mbps 下连续发送多条命令存在间歇性不到达；MCU 侧 DMA 仍为 active 且 `rx_restart_failures=0`。当前自动化测试采用每条命令独立打开 COM3，并以响应确认后再推进。
- 在修复 VCP 连续发送可靠性前，上位机必须逐条等待确认并允许超时重试，不能把“已写入 COM3”当作 MCU 已接收。
