# UI 审计整改记录

> 文件编码：UTF-8
> 整改日期：2026-07-26
> 依据：`Docs/UI管理审计报告_20260726_UTF-8.md`
> 范围：审计报告第一阶段（卡死路径）+ 部分第二/三阶段项

## 1. 任务所有权调整（P0-01）

新增 `APP/RTOS/app_calibration_worker_task.c`（任务名 `CalWorkerTask`，
优先级 BelowNormal，栈 8 KiB），由 DisplayTask 初始化阶段创建。

- `AppCalibrationBoardPort_Register()`、`AppCalibrationService_Init()`、
  `AppCalibrationService_Run()`、`AppCalibrationBoardPort_Run()` 全部移入
  worker，DisplayTask 循环只剩 `AppUiRemoteControl_Run()` + `App_LvglRun()`。
- `AppCalibrationService_RequestFinishSession()` 与
  `RequestConfirmCandidate()` 改为“UI 线程置请求标志，worker 的 Run()
  执行安全收尾 / QSPI 写入”。UI 回调链路中不再存在任何继电器、ADC
  等待或 QSPI 擦写。
- 服务新增 `s_service_ready` 门禁，初始化完成前拒绝 Enter/Start 等请求。
- 请求标志在状态离开对应阶段时被丢弃（防过期请求误触发）。

## 2. MainTask 忙等修复（P0-02）

`app_main_task.c` 两处 `AD9226_AcquireLatestFrame()` 等待循环改为
`osSemaphoreAcquire(AdcFrameReadySemHandle, 1 tick)` 有界阻塞。DMA 帧完成
回调会释放该信号量，首帧响应延迟不变，但等待期间让出 CPU，AboveNormal
的 MainTask 不再饿死 Normal 的 DisplayTask。

## 3. 状态与按钮策略（P1-01 / P1-02）

`UI/Adapter/app_ui_adapter.c`：

- `FINISHED` 拆分为 `TRACKING`（锁相输出中）与 `ANALYSIS DONE`（锁相已停）。
  锁相状态变化时 50ms 轮询内自动更新文案（`app_ui_refresh_tracking_state`）。
- RUN/STOP 按钮指针常驻保存，`app_ui_refresh_run_buttons()` 每轮询周期刷新：
  - RUN 可点条件：`!AppMain_IsRunning() && !AppCalibrationService_IsExclusive()`
  - STOP 可点条件：`AppMain_IsRunning() || AppPhaseLockTask_IsRunning()`
- Phase +/- 使能规则未变（锁相运行中禁用），但文案不再误导。

## 4. 串口页面生命周期（P1-04 / P1-05）

`APP/SerialControl/app_ui_remote_control.c`：

- 串口 `PAGE` 创建的动态页面注册 `LV_EVENT_SCREEN_UNLOADED` 自动删除，
  与触摸导航 `lv_obj_add_screen_create_event` 行为一致，消除 LVGL heap 泄漏。
- `PAGE` 加载后立即调用 `AppUiAdapter_NotifyPageChanged()` 与
  `AppCalibrationUiAdapter_Run()` 完成绑定，同一命令批次内的后续 `TAP`
  不再落入未绑定窗口。

## 5. 校准页绑定解耦（P1-06 / P1-07）

- `AppCalibrationUiAdapter_Run()` 从 `AppUiAdapter_Run()` 内部移出，
  由 `App_LvglUiRun()` 直接调用：不再受 Monitor Adapter `s_initialized`
  与 50ms 轮询门限约束。
- 绑定检测每个 LVGL 循环（5ms）执行；快照渲染保留 50ms 节流。

## 6. 触摸驱动加固（P1-08）

`BSP/Touch/app_touch_gt9xx.c`：

- I2C 读取失败累计计数；连续失败 5 次触发控制器重新初始化（复位时序）。
- pressed 状态超过 300ms 未见有效数据帧时强制释放（读取失败与无新数据
  两条路径都检查），并计数 `stale_release_count`。
- 新增 `App_TouchGetDiagnostics()` 输出错误、释放、重初始化计数与
  最后有效帧 tick。

## 7. UI 交互自监视（P1-09）

新增 `APP/Debug/app_ui_monitor.c`：

- DisplayTask 每循环记录心跳 tick、循环耗时、历史最大耗时，
  ≥50ms 计一次 overrun；
- 每 1s 采样 `lv_mem_monitor()`：使用量、最大连续空闲块、碎片率；
- 汇总触摸诊断计数。

串口 `RTOS` 命令新增输出：

```text
[CTRL] UIMON heartbeat=<tick> loops=<n> last_ms=<n> max_ms=<n> overruns=<n>
[CTRL] LVGL used=<bytes>(<pct>%) free=<bytes> biggest=<bytes> frag=<pct>%
[CTRL] TOUCH errors=<n> stale_rel=<n> reinit=<n> last_valid=<tick>
```

巡检判据：

- `heartbeat` 停止增长 → DisplayTask 卡死；
- `max_ms` 持续增长 / `overruns` 上升 → UI 循环被拖慢；
- `biggest` 持续下降或 `frag` 升高 → 切页泄漏 / 碎片化前兆；
- `stale_rel`、`reinit` 非零 → 触摸链路曾出现异常并已自动恢复。

## 8. 占位按钮（P2-01）

页面绑定时递归禁用以下标签的按钮（`LV_STATE_DISABLED`）：
Control 页 `Select`/`Edit`/`APPLY`；System 页 `Touch Test`/
`Display Test`/`Memory Status`。业务逻辑落地后从
`s_placeholder_button_labels` 表中移除即可。

## 9. 整改后回归修复（2026-07-26 晚）

**现象**：上电复位后进入测试页，页面停在 `IDLE / PRESS START`，
全部按钮不可用（表现为“卡死在测试页”）。

**根因**：

1. `configTOTAL_HEAP_SIZE` 仅 40KiB，CubeMX 6 个任务栈已占约 27KiB；
   CalWorkerTask 首版使用动态分配的 8KiB 栈，内核堆不足导致
   `osThreadNew` 失败（或堆濒临耗尽）→ 校准服务永不初始化。
2. `app_calibration_ui_bind` / `Run` 在服务未就绪时调用
   `RequestEnter` 被就绪门禁拒绝后不重试，页面永远停留在 IDLE。

**修复**：

1. CalWorkerTask 改为静态栈（8KiB `.bss`）+ 静态 `StaticTask_t`
   控制块，完全不占用 FreeRTOS 内核堆，创建不再可能因堆不足失败；
2. `RequestEnter` 失败时转入 `s_reenter_pending` 持续重试，
   worker 初始化完成后页面自动进入 READY。

## 10. 测试页 REVIEW 状态交互修复（2026-07-26 晚，第二批）

**现象 1**：测试页 START（输出自检）结束进入 REVIEW 后，
TEST SETUP 的 INTERNAL/EXTERNAL 与两个下拉框保持灰色不可用。

**修复**：输出自检不产生待确认校准数据，REVIEW 状态下允许改选并
直接重测——`app_calibration_ui_render` 的 `selection_locked` 排除
自检 REVIEW；`AppCalibrationService_SetSelection` 同步放行该状态。
其他校准项目在 REVIEW 仍锁定，防止覆盖未导出数据。

**现象 2**：打开 ADC DISPLAY ON 后波形窗口无各测试项波形，
长期停留在 WAIT FOR ADC。

**根因与修复**：

1. 开启显示时 UI 强制"等待新采集帧"，而测试结束后不再有新帧
   → 改为开启即渲染缓存中的最近一帧，新帧按序列号照常刷新；
2. READY/REVIEW 空闲态板级不做任何采集，显示开启也无实时数据
   → `AppCalibrationBoardPort_Run` 新增空闲预览：显示开启、校准
   独占且状态为 READY/REVIEW 时每 250ms 采一帧刷新预览窗口。
   测试运行期间仍由各测试项采集驱动（每项含 1s 波形停留）。

## 12. 第三批小项整改（2026-07-26 晚）

本批完成审计遗留的可独立落地项，未触及第二/三/四阶段架构主线：

1. **P1-03**：`app_calibration_ui_adapter.c` 全部业务回调不再 `(void)`
   丢弃返回值；被拒时计数并输出 `[UI] REJECT <动作> state=<n> error=<n>`。
2. **P2-04（诊断部分）**：Test/Calibration 绑定完成后统计缺失控件，
   输出 `[UI] BIND <页> missing=<n> first=<名>`；Monitor 绑定失败输出
   `[UI] BIND MONITOR FAIL`，不再静默停用页面逻辑。
3. **P2-05（TAP 回传部分）**：串口 TAP 回显后追加业务快照行
   （MAIN running/tracking、PHASE deg、CAL state/error/can_start），
   上位机不再把 LVGL 派发成功误当业务受理。
4. **P2-06**：《当前主线索引》任务表与 UI 输出描述更新为当前架构，
   补记 SerialControlTask/CalWorkerTask 所有权。

仍保留的第 11 节大项需按审计第八节顺序分阶段推进，每阶段独立
构建、烧录与真机回归，不在单轮内合并执行。
