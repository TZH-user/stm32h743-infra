## 2026-07-18 E3 可见验收出口决策

### 独立接收结论

- 用户释放 COM3 后，使用“先监听、后复位”的顺序完成 4 秒独立捕获。
- 实收内容与确定性格式和用户 VOFA+ 截图一致，因此串口可见出口由间接证据升级为
  字节级直接证据。
- VOFA+ 曲线区出现斜线/锯齿是 FireWater 解析 E3 文本造成的显示伪迹，不作为
  ADC 波形或频谱证据；E3 日志模式只验收底部文本。

### 决策

1. 调试器内存值只作为开发证据，不作为用户可见验收出口；E3 必须同时提供
   串口文本和屏幕正式主候选读数。
2. 不在 MainTask 直接格式化文本。MainTask 只提交一次结果快照，PrintfTask
   继续独占 USART1，避免破坏任务时序和 MainTask 仅 200 B 的真实余栈。
3. 默认串口输出简短结果，不输出完整 4096 点频谱；ADC 单帧仍通过
   `APP_OUTPUT_DEFAULT_MODE=2U` 可直接恢复。
4. 屏幕图形仍是 128 点 Preview；正式 4096 点结果只驱动状态、候选数、主频和 SNR，
   不把预览频谱冒充正式 E3 频谱。
5. 构建后必须显式 objcopy 再烧录；仅 ELF 时间更新不能证明 HEX 是最新固件。

### 已验证结论

- 20+100 kHz 双音下，串口结果快照已发送且无丢弃/错误，UI 正式结果快照有效。
- 格式化移入 PrintfTask 后，MainTask 最低余栈仍为 50 words；PrintfTask 为
  54 words，真实完整输出路径无栈溢出。
- 最新 HEX 显式刷新并烧录后，UI SNR 字段由旧镜像的 0 正确变为 4450 q100，
  证明最终板上运行的是最新镜像。

### 边界

- COM3 当前被用户串口助手占用，未强制抢占；最终字节级可见结果等待用户确认。
- E3 屏幕只显示排名第一候选；全部候选以串口列表为准。E4 再设计双路参数页面。

### 回退

- 使用 Git 节点 `153d41c` 回退到可见输出补齐之前。

## 2026-07-18 E3 双音、弱路边界与最终放行

### 决策

1. DG4062 CH1/CH2 通过用户搭建的 OPA690 求和电路接入同一 AD9226 通道；
   启用前先在双路 OFF 状态下实测基线，基线 RMS 1.6227 code、削顶 0、候选 0。

3. 幅值差异测试固定 20 kHz 强路为 0.02 Vpp，降低 100 kHz 弱路，
   同时核对幅值门限和 SNR 门限。

- 失败侧 SNR 仍高于 12 dB，切换由 8 code 幅值门限决定；门限逻辑与实测一致。
- E3/G3 的单音、双音、轻微频率偏差、幅值差异和运行安全放行条件全部满足。

- E3 不包含精确幅相、残差、正弦/三角波分类或屏幕正式结果绑定。

## 2026-07-18 E1 三档采样率门禁

### 决策

1. 获批创建 `APP/SignalDetect`，但只包含配置、公共接口和统计实现三个文件。
2. 保持 MainTask 为唯一业务调度者，按 512 kS/s、1.024 MS/s、2.048 MS/s 串行执行，
   每档逐帧启动、等待、停止和统计 100 帧。
3. 不新增采集任务、FFT任务、分析任务、采集副本队列或通用状态机。
4. 门禁过程不输出统计文本，只在全部门禁结束后把最高采样率最后一帧交给 UI 和
   OutputTask，避免污染双列波形格式。
5. `overwritten_frames`、`notification_overflows` 和 `dma_errors` 均纳入失败条件。

### 真机发现与修正

- 首轮发现每次停止清理会误发布一次迟到 DMA 完成，造成完成数翻倍或通知溢出。
- 观测证明 Stop 入口前只有一帧完成，第二次计数发生在 Stop 内部。
- 最小修正为 Stop 入口先将 `running=false`，不改定时器、DMA、Cache、MPU 或 IOC。
- 修正后每次启动严格对应一次 DMA 完成，三档各 100/100 通过。

### 代价与边界

- 为保证同一任务在第一帧到达后立即停止，E1 门禁采用有超时的短时轮询；三档总运行
  1,701 ms，完成后 MainTask 永久休眠，不形成持续 CPU 占用。
- 当前只验证现场输入，固定中点、指定 20/100 kHz、双信号和削顶仍需人工切换信号源。
- VCP 存在可恢复背压，但上层重试后无最终丢包；后续更大输出量仍需继续监控。

### 回退

- 修改前 Git 基线为 `b1da966`，本阶段由独立提交保存。

## 2026-07-18 单帧串口兼容桌面波形分析器

### 原方案

`AppOutput_PublishAdcFrame()` 每行只输出一个 ADC 码值。该格式可供 VOFA+ 单通道

1. 第一列输出从 0 开始的样本序号，第二列输出 12 位 ADC 原始码值。

### 依据

- 当前 `MainTask` 只调用 `AppOutput_PublishAdcFrame()` 一次，因此只修改完整帧接口即可满足需求，且不会扩散到连续采集主线。

- Debug 配置、编译、size 和 objcopy 全部成功。
- 最终 ELF 中没有 `StartFftTask`，因此双列 ADC 文本不会与串口 FFT 输出混合。

## 2026-07-19 E6 双分量联合模型

4. 不替换每帧少量的 `atan2f/sqrtf`，避免相位和幅值精度退化。

### 依据

- 源码审计确认E4与E5此前在4096点循环内存在逐点 `sinf/cosf`，属于真实热点。
- CMSIS-DSP当前工程已有公共表和FFT子库，新增控制函数不引入第三方依赖或第二套表管理机制。
- 链接结果确认活跃对象已无 `sinf/cosf` 未解析引用，且DTCMRAM实际减少约2 KiB。

### 真机门禁

- E7必须保持原双音频率与类型识别结果。
- 锁相单帧处理必须低于5120 us，DAC补数超时、欠载和任务通知错误均为0。
- 查表后相位误差不得持续漂移；不以仅构建通过代替真机验收。

## 2026-07-24 DAC链路隔离与PI控制最终方案

### 决策

1. DAC请求独占`DMA2_Stream0`；ADC和USART继续留在DMA1，避免三个高频流共享DMA1控制器路径。
2. DAC最终采样率取1.6 MS/s，32768点缓冲不变，半缓冲时限10.24 ms；不继续扩大缓冲。
3. 控制器保持PI-DPLL，P=0.12、I=0.05、单帧频率步进上限1 Hz；不加入对块级相位噪声敏感的D项。
4. 保留DAC错误现场快照；一旦DAC停止，PhaseLockTask同步结束会话，不保留虚假的锁定状态。

### 依据

- 故障现场为DMA传输错误`HAL_DMA_ERROR_TE`，不是补数计算超时；优先级、FIFO/burst、内存bank和1.0 MS/s降速均未消除旧DMA1故障。
- 迁移到DMA2后，1.0 MS/s和最终1.6 MS/s各完成120秒零错误测试。
- 1.6 MS/s下最大补数2865 us，只有10.24 ms窗口的约28%；扩大缓冲没有必要，且会增加延迟和RAM占用。
- 降低PI增益后，35 kHz三角波与70 kHz正弦波的跟踪频率稳定在约34999.56/69999.13 Hz，内部相位误差无持续漂移。

### 边界

- 串口证明数字链路连续和内部锁定稳定，但最终0.8 Vpp、模拟缓冲固定相移和肉眼可见抖动仍应以示波器为准。
- 暂停式GDB会人为造成实时DAC中断；资源诊断后必须复位并重新用非侵入串口验收。

## 2026-07-25 初相位控制方案

### 决策

1. 不新增 RTOS 任务；相位设置、跟踪参考和 DAC 更新继续由 `PhaseLockTask` 管理。
2. 仅在两个识别结果均为正弦且 `fB/fA=N` 为整数时启用题目相位模式。
3. A' 的锁相相位定义公共时间原点，B' 参考采用 `phase_B=N*phase_A+phi`。
4. 公共基频取 `0.5*(tracked_fA+tracked_fB/N)`，输出频率为 `fA=f0`、`fB=N*f0`，避免两路独立估频微差造成初相位慢漂。
5. 相位由 UI 减/加键或任务公开接口设置，范围 `0..180 deg`、步进 `5 deg`；运行中修改会在后续跟踪和 DAC 半缓冲更新中生效。

### 依据

- 题目发挥部分（2）明确限定双正弦和 `fB` 为 `fA` 整数倍，并定义 `A'=sin(omega_A*t)`、`B'=sin(omega_B*t+phi)`。
- 双 DAC 共用 TIM6 触发和同一个双通道 DMA 数据字，数字时间基一致。
- 1.6 MS/s Q32 相位累加器配合 512 点 Q15 正弦表和两位线性细分，数字相位网格远小于题目 `5 deg` 容差。

### 边界

- 非整数倍或含三角波时不宣称初相位控制，保持既有独立锁相行为。
- 编译、数学边界和内部遥测只能证明软件路径；最终 `+/-5 deg` 必须包含片内 DAC 与外部缓冲链的示波器实测。
- 本方案不改变既有 DMA 分配、1.6 MS/s DAC、32768 点缓冲和 PI 参数。

## 2026-07-25 相位设置时序收敛

### 决策

## 2026-07-25 校准 QSPI 分区与掉电安全决策

### 决策

1. 不在业务模块散落 Flash 地址；由 `app_board_flash_memory_map.h` 统一管理 8 MiB W25Q64 分区。
2. 校准区使用 `[0x600000, 0x7FE000)`，避让参考工程前部壁纸区以及最后两个 4 KiB 的 OCXO/Sweep 扇区。
3. 元数据采用两个 4 KiB 日志扇区轮换；切换时先在另一扇区建立有效快照，避免先擦除唯一状态。
4. Profile 使用三个独立 4 KiB 物理槽，元数据映射 `active/pending/previous` 逻辑角色，不通过复制整份 Profile 完成角色切换。
5. `CONFIRM` 只建立下次启动的 `pending`；启动加载成功后再原子提升为 `active`，旧 `active` 保留为 `previous`。
6. 原始会话使用 64 字节定长追加槽，记录 Session Header、Measurement Point 和 Finish；payload CRC、整槽 CRC、commit marker 共同判断记录有效性。
7. 会话日志写满时返回范围错误，不自动环回擦除旧数据；后续必须由明确的导出/清理流程释放空间。

### 依据

- 参考工程 CodeGraph 与源码确认 W25Q64 为 8 MiB、4 KiB sector、256 B page、JEDEC ID `0x00EF4017`。
- 参考工程已占用 `0x000000..0x0BD000` 壁纸区、倒数第二扇区 OCXO 和最后扇区 Sweep。
- NOR Flash 只能稳定地把 bit 从 1 编程为 0，任意覆盖元数据或原地修改 Session Header 都会引入掉电和擦除风险。
- 固定槽 + 最后提交标记能够把“完整记录”和“掉电残缺尾记录”区分开。

### 边界

- 当前只有静态构建证据，没有真实 W25Q64 的 JEDEC、擦写、掉电和磨损测试证据。
- 二进制 Profile 当前按同一 schema 的 STM32 C 结构保存；跨语言上位机导入/导出仍需另定义显式字节序和字段宽度协议。
- ADC/DAC Port 与板端绝对安全量程未完成前，START 继续硬禁用；QSPI READY 不等于允许真实 DA 激励。

## 2026-07-26 内部回环逐步逼近与平台保护决策

### 决策

1. 当前内部回环只开放 `DAC1 -> AD9226`；DAC2 与负电压激励继续拒绝。
2. DAC 标称扫描上限为 3.0 V，不因前端声明 `±5 V` 就输出到电源轨；步进 50 mV、驻留 25 ms，每点采 4096 样本。
3. 只有 ADC 接近 0/4095 且贴边比例超限才标记 `adc_clipped`；远离码限但连续三步增量消失时标记 `transfer_plateau`。
4. 平台、无响应、反向突变、IO 错误和用户 STOP 都必须先停 ADC、DAC 归零/停止、继电器双低，再结束会话。
5. 内部回环只表征组合链路，不能把 DAC 和 ADC 的绝对增益/零偏拆开；没有外部参考时不自动生成可应用 Profile。
6. 8 Mbps 串口控制采用请求-确认-超时重试，连续无确认发送不作为受支持工作流。

### 依据

- 两次实机扫描均在标称 1.10 V 后稳定于约 1618 code，且 ADC 贴边计数为 0；区分平台与数字削顶可避免错误扩大扫描或错误拟合。
- 两次停止后的 ODR、DOR1、运行标志和 CPU Fault 寄存器均证明安全收尾有效。
- VCP 丢失命令时 MCU DMA 仍 active、restart failure 为 0、received_bytes 未增加，问题位于解析器之前。
