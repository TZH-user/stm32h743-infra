# AD9226 与片内双 DAC 校准架构实施计划

日期：2026-07-25
工程：`F:\STM32\stm32project\VSCodeCMAKEProject\signal_separation`

## 1. 结论

本工程采用“可移植校准核心 + 工程编排服务 + 硬件 Port + QSPI 存储 + 独立全屏 UI”的五层结构。

校准核心只接收测量点并输出拟合结果，不直接依赖 ADC、DAC、继电器、RTOS、LVGL 或 Flash。当前工程先接入 AD9226、STM32H743 片内 DAC1/DAC2；未来工程通过替换 Port 和来源描述表复用核心。

## 2. 已确认需求

1. 两个继电器分别控制：
   - 外部输入端在外部信号与装置内部 DAC 之间切换。
   - 内部 ADC 在正常测量链路与 DAC 校准回环之间切换。
2. 继电器 GPIO、电平组合和稳定时间暂未确定，首阶段只定义抽象接口与安全默认态，不写死引脚。
3. 校准分为：
   - 内部校准：装置内 DAC 到 AD9226 的回环测量。
   - 外部校准：STM32 记录原始测量数据，导出给上位机拟合，再导入校准结果。
4. 首阶段数据来源：`DAC1 -> ADC`、`DAC2 -> ADC`、`外部输入 -> ADC`。
5. 校准内容：
   - DAC 增益、零偏。
   - ADC 增益、零偏。
   - 幅频响应。
   - 双 DAC 通道间幅度差、相位差。
   - AD/DA 安全幅度上下限。
6. DA 激励必须使用限幅、斜坡逼近和超限立即停止，避免阶跃或错误设置损坏输出级。
7. 校准界面具有最高资源独占权。校准期间暂停普通分析、锁相、无关 UI 数据刷新和无关 AD/DA 输出。
8. 原始测量会话和校准配置存入外部 QSPI Flash，参考：
   `F:\STM32\stm32project\VSCodeCMAKEProject\Simple_wireless_IQ_demodulation\Core\App\BoardFlash`
9. 新校准结果拟合或导入后先进入待确认状态：
   - 取消：丢弃待确认结果，保留旧配置。
   - 确认：保存为下次上电生效配置，但不立即改变本次运行参数。
   - 立即作用：本次运行切换到新配置，按钮更名为“撤销作用”。
   - 撤销作用：本次运行恢复旧配置；已确认的新配置仍保留下次上电生效语义，除非后续另行设计“取消下次生效”。

## 3. 重要工程边界

### 3.1 可证明边界

仅用未校准 AD 测量未校准 DA，只能得到 `DAC -> 模拟链 -> ADC` 的联合传递误差，不能从同一组回环数据唯一分离出 ADC 与 DAC 的绝对增益和零偏。

因此：

- 内部校准负责回环一致性、通道相对误差、幅频响应和运行安全边界。
- ADC/DAC 绝对增益与零偏由外部参考设备和上位机拟合提供，再导入固件。

### 3.2 当前暂定项

- 继电器真值表、有效电平、切换时序和安全态由后续硬件信息填入 `CalibrationRelayPortConfig`。
- 具体幅度上下限、斜坡步长、驻留时间和频点表均作为板级配置，不放入通用核心常量。
- 页面文案首轮使用英文，避免当前工程尚未接入中文字体；业务按钮语义在代码和计划中保留中文说明。

## 4. 分层架构

```text
UI/Calibration Page
        |
        v
AppCalibrationService（独占、状态机、进度、确认/应用/撤销）
        |
        +--> CalibrationCore（纯 C 拟合、验证、结果结构）
        |
        +--> CalibrationSourcePort（来源枚举与采样数据提供）
        +--> CalibrationRelayPort（继电器路由与安全态）
        +--> CalibrationDacPort（限幅、斜坡、停止）
        +--> CalibrationAdcPort（AD9226 采帧）
        +--> CalibrationStoragePort（QSPI 会话/配置/回退）
```

### 4.1 `CalibrationCore`

建议独立目录：`CalibrationCore/include`、`CalibrationCore/src`。

职责：

- 接收来源 ID、通道 ID、目标设置值、实测值、频率、相位和质量标志。
- 执行线性增益/零偏拟合、幅频表生成、双通道幅相差计算。
- 输出带版本、长度和 CRC 所需字段的 `CalibrationProfile`。
- 检查点数、单调性、残差、上下限和拟合有效性。

禁止依赖：HAL、CMSIS-RTOS2、LVGL、具体 Flash 驱动和全局硬件句柄。

### 4.2 `AppCalibrationService`

建议采用非阻塞状态机，由单一校准编排上下文拥有硬件资源。建议状态：

`IDLE -> ACQUIRE_EXCLUSIVE -> SAFE_SHUTDOWN -> ROUTE_SOURCE -> SETTLE -> RAMP_OUTPUT -> CAPTURE -> STORE_POINT -> NEXT_POINT -> FIT_OR_EXPORT -> REVIEW -> COMMIT_PENDING -> ACTIVE_RUNTIME -> ROLLBACK_RUNTIME -> RESTORE_SAFE`

服务负责：

- 拒绝并发 RUN、锁相或第二次校准请求。
- 先停止 ADC/DAC，再切继电器；切换后等待稳定，再启动目标 AD/DA。
- 校准异常、用户取消、超时或越限时统一进入安全收尾。
- 只发布快照给 UI，UI 不直接调用 HAL 或写 Flash。

### 4.3 来源无关接口

来源由描述表注册，首阶段枚举：

- `CAL_SOURCE_DAC1_LOOPBACK`
- `CAL_SOURCE_DAC2_LOOPBACK`
- `CAL_SOURCE_EXTERNAL_INPUT`

每个来源提供显示名、能力位、允许量程、路由请求和采样回调。以后增加外部 ADC、DDS 或其他 DAC 时不修改拟合核心。

### 4.4 存储模型

QSPI 至少划分为两个逻辑对象：

1. 测量会话日志：只追加的原始点记录，可分页导出。
2. 校准配置槽：`previous`、`boot_pending/current` 和元数据。

建议所有记录包含：magic、schema version、board ID、source ID、sequence、payload length、payload CRC、record state。

Flash 具体地址、擦除粒度和冗余策略在检查 BoardFlash 实现及当前 QSPI 分区后确定，不在本计划中臆测。

## 5. 校准安全策略

1. 校准入口先申请全局运行模式所有权；申请失败不得切继电器或启动 DAC。
2. 关闭无关 DAC 通道并停止普通 ADC 采集、分析、锁相和波形发布。
3. 每次改变 DAC 目标值必须经过板级上下限夹取与斜坡发生器。
4. 斜坡每步后检查：ADC 上下限、饱和码比例、DMA 错误、超时和用户停止请求。
5. 任一错误立即关闭 DAC、停止 ADC、继电器回安全态，并保留故障点供导出。
6. UI 离开校准页不等同于强制中断；若校准运行中，应先弹出停止确认。

## 13. 继电器 GPIO 与已接入逻辑

### 13.1 引脚与连接器

- `CAL_RELAY_INPUT_SEL`：`PC6`，核心板排针 `P2-18`。
- `CAL_RELAY_ADC_LOOP`：`PC7`，核心板排针 `P2-16`。
- 两脚同属 GPIOC，可通过一次寄存器写入同步改变，降低中间组合态风险。

### 13.2 真值与安全态

| PC6 | PC7 | 固件语义 |
| --- | --- | --- |
| 0 | 0 | 正常任务/外部输入链路，亦为上电、退出和故障安全态 |
| 1 | 1 | `PA4(DAC1) -> AD9226` 校准回环 |
| 0/1 | 1/0 | 固件不主动输出的中间组合态 |

- `DAC2 -> ADC` 当前没有硬件路由依据，Service 标记为 `SOURCE NOT ROUTED` 并禁止 START。
- GPIO 采用推挽输出、低速、无上下拉，CubeMX 上电初始值为低。
- `app_calibration_board_port.c` 在注册 Port 时再次强制两脚为低；退出校准和错误收尾同样恢复低电平。

### 13.3 验证结果与电气边界

- 用户提供的核心板 IO 引出图确认 PC6/PC7 已分别引到 P2-18/P2-16。
- CubeMX 生成返回 `OK`；工具后检查仅因本工程没有 `Core/Inc/freertos.h` 报预期文件缺失，实际更新仅为 `main.h` 与 `gpio.c`。
- 最新 ARM GNU Debug 构建通过，ELF/HEX/BIN/MAP 已同步生成。
- 禁止使用 MCU GPIO 直接驱动裸继电器线圈；必须经过继电器模块逻辑输入、三极管/MOSFET 或光耦驱动，并具备续流保护。

## 14. QSPI BoardFlash 与校准持久化布局

### 14.1 有依据的硬件参数

- Flash：W25Q64，容量 `8 MiB`，JEDEC ID `0x00EF4017`。
- 擦除粒度：`4 KiB sector`、`64 KiB block`；编程页：`256 B`。
- 当前工程 QSPI 引脚与参考工程一致：PG6/NCS、PF6/IO3、PF7/IO2、PF8/IO0、PF9/IO1、PF10/CLK。
- QSPI 外设加入后的 CubeMX 代码生成和 ARM GNU Debug 构建均已通过。

### 14.2 统一 memory map

| 区域 | 起始地址 | 结束地址（不含） | 用途 |
| --- | ---: | ---: | --- |
| Wallpaper 保留区 | `0x000000` | `0x0BD000` | 兼容参考工程已有壁纸资源 |
| 校准元数据 A/B | `0x600000` | `0x602000` | 两个 4 KiB 日志扇区，轮换保存原子状态快照 |
| Profile A/B/C | `0x602000` | `0x605000` | `active/pending/previous` 三个逻辑角色 |
| 预留扩展 | `0x605000` | `0x610000` | 后续导出索引、板号或 schema 扩展 |
| 校准会话日志 | `0x610000` | `0x7FE000` | 原始 Session/Point/Finish 定长追加记录 |
| OCXO 保留扇区 | `0x7FE000` | `0x7FF000` | 兼容参考工程倒数第二扇区 |
| Sweep 保留扇区 | `0x7FF000` | `0x800000` | 兼容参考工程最后一扇区 |

分区常量集中在：
`APP/BoardFlash/app_board_flash_memory_map.h`，禁止在业务文件散落重复地址宏。

### 14.3 掉电安全语义

1. 元数据记录固定 64 字节，包含 generation、日志尾偏移、三个 Profile 槽角色、CRC 和最后写入的 commit marker。
2. 当前元数据扇区写满后，先擦除另一扇区并写入完整新快照，再切换当前扇区；不先破坏唯一有效状态。
3. Profile 写入独立 4 KiB 槽，先擦除目标槽、写入 payload 和 CRC，最后写 commit marker，再读回验证。
4. `CONFIRM` 只更新 `pending`；下次上电加载成功后，元数据把旧 `active` 转为 `previous`，把 `pending` 转为 `active`。
5. `APPLY NOW` 仅改变当前 RAM 运行 Profile；`UNDO APPLY` 恢复进入立即作用前的 RAM Profile，不撤销已经确认的下次上电版本。
6. 会话日志使用 64 字节定长槽，依次保存 Session Header、Measurement Point 和 Session Finish；CRC 或 commit marker 无效的尾记录不作为有效数据。

### 14.4 当前验证边界

- 有依据：代码已通过 ARM GNU Debug 编译、链接和镜像生成。
- 未验证：尚未烧录，因此不能宣称 JEDEC ID、擦除、写入、掉电恢复或元数据轮换已在实机通过。

### 17.5 ADC/DAC 物理编码边界

- AD9226 当前以 12 bit offset-binary 码表达双极性输入：代码 0 约对应负端，2047/2048 附近约对应 0，4095 约对应正端。
- 片内 DAC 是单极性输出：DAC code 0..4095 对应约 0..VDDA；本轮自检的 3.00 V 是 DAC 安全上限，不是 ADC 的 ±5 V 全跨度。
- 对 ±5 V ADC 总跨度，4095 / 10 V = 409.5 code/V 是暂定比例；DC 采用 DAC=0 基线后的有符号差值幅度，AC 采用去均值后的拟合幅度，因此不把 ADC 码直接当作单极性电压。
- 当前实现仍未把 offset-binary 到物理电压的转换抽成独立板级配置；在外部参考测量前，不能据此生成绝对增益/零偏 Profile。
