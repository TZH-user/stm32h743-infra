# AutoBench 离线阶段实施方案

> 日期：2026-07-27  
> 编码：UTF-8  
> 状态：已实施并通过离线验收

## 目标

在 DG4062、DS4014E 和开发板全部下电的条件下，完成计划 schema、解析、安全上限、
dry-run、模拟/board_vcp、PC 指标和报告闭环，同时保证所有异常路径都不会尝试开启或
关闭仪器输出。

## 架构

```text
JSON plan
  -> plan.py（结构 + 5 Vpp 硬上限）
  -> runner.py（dry-run / simulate / board_vcp / scope硬门禁）
  -> signals.py（模拟或CSV）
  -> metrics.py（Vpp/THD/SNR/frequency）
  -> reports.py（CSV/Markdown/JSON/PNG）
```

## 与原任务书的受控差异

1. **有依据**：原任务书要求“第一步探测仪器”，但当前用户明确仪器下电并禁止网络探测；本阶段改为完全不探测。
2. **有依据**：原任务书要求“运行结束自动关闭 DG4062 输出”，但关闭也是硬件写操作，且本阶段从未开启输出；改为零连接、零输出控制。
3. **有依据**：原任务书建议复制仪器驱动；本阶段为避免 DS4014E 双真源，AutoBench 只保留 Toolkit 路径与硬门禁，后续上电复用唯一 Toolkit。
4. **有依据**：原任务书要求修改 `F:\STM32\.gitignore`，但本任务明确禁止；因此保持不改并在 README 明示未纳管风险。
5. **有依据**：真实 T2/T3 直通验收无法在下电条件执行，按任务授权使用模拟与 board_vcp 完成软件验收，硬件结论不伪造。

## 安全不变量

- 全局幅度硬上限固定为 5 Vpp，计划不能提高。
- `--dry-run` 只读取本地 JSON。
- scope 分支在加载 DS4014E Toolkit 前抛出 `OfflineHardwareBlockedError`。
- 离线 runner 没有 socket/serial sender，也没有 DG4062 输出开关调用。
- 报告显式记录 `hardware_access_attempted=false` 与 `instrument_output_changed=false`。

## 已验证结果

- 10/10 自动测试通过。
- 20 点模拟幅频、1 kHz THD、5 点频率精度、board_vcp 报告均 PASS。
- 6 Vpp 计划退出码 3；scope 非 dry-run 退出码 4。

## 后续阶段

只在用户确认仪器上电、物理连接与目标通道后，按 Toolkit 审计文档的最小矩阵逐项推进。
在恢复语义完成前，不进入自动 capture 和 DG4062 输出控制。
