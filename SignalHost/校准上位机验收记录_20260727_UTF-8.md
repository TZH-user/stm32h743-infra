# SignalHost 校准上位机验收记录（2026-07-27，UTF-8）

## 1. 结论

- **有依据：`HOST_UI_TEST_PASS`。** 本机实际运行 50 项 serial fake、回放、拟合、
  持久化与 GUI 自动测试，全部通过。
- **有依据：`PROTOCOL_STATIC_PASS`。** 检查器直接读取当前固件真源和协议宏，核对
  2 Mbps、IMPORT `int32[5]`、短格式 EXPORT B/P/E、POINT 结构与 CRC、CAL UNDO
  Service→Worker 路径。
- **有依据：`HARDWARE_PENDING`。** 本阶段未打开 COM3、仪器或 ST-Link，未烧录、
  复位或执行真实 CAL/QSPI；测试结果不代表真实校准精度或掉电保持通过。

串口层或测试目录。现场已有 `tkinter`、`pyserial`、`numpy`、`matplotlib`，没有
`pytest`。本次采用标准库 `unittest` 与 `tkinter`，没有新增依赖或重建工程，原
`CMakeLists.txt`、`src\host_main.c` 和 `tools\run_case.ps1` 未修改。

SignalHost 已初始化 `.codegraph` 索引，并用 CodeGraph 审计 IMPORT 的 CRC、拟合字段、
Session 命令和 fake 调用链；固件工程索引用于核对 Calibration Service 生命周期。

## 4. 固件静态协议证据

静态检查读取：

- `APP\RTOS\app_serial_control_task.c`
- `APP\Calibration\app_calibration_board_port.c`
- `CalibrationCore\src\calibration_core.c`
- `Core\Src\usart.c`

核对结果：

- USART1：`2,000,000 baud`。
- 命令：`PING/STATUS/RTOS/CAL STATUS/CAL EXT/IMPORT/EXPORT/CONFIRM/APPLY/UNDO`。
- POINT：queued 行不是完成；最终行为 `[CAL] EXT n=... ref_mv=... mean=... crc=...`。
- Import CRC：小端 `int32[5]`，字段为 gain/offset/R² ppm/residual millicode/points；
  向量 `{-414002,2056898,999981,7439,38}` 的 CRC32 为 `6B0AA818`。
- 生命周期：confirm 产生 pending，apply 成功后 pending 转 active。
- EXPORT 线上格式为 `B/P/E` 短字段；POINT 的 `r/m/p` 是 binary32 原始位，CRC 对应
  `CalibrationMeasurementPoint` 的 20 字节 payload。
- UNDO 复用既有 Service 请求并由 Calibration Worker 执行；成功状态包含 `applied=0`。
- Host 与固件 IMPORT 字段顺序、缩放和 CRC payload 已静态对齐。

## 5. GUI 安全证据

- 默认 transport 为 `Serial Fake`，且 fake 不枚举 Windows COM 口。
- `SerialTransport.open()` 在未显式允许时抛出 `PermissionError`；测试对 `COM3` 仅做
  该门禁断言，没有打开端口。
- 真实串口采用有界队列和后台 I/O thread；本阶段未启动该 thread。
- 配置缺失显示 `NOT_CONFIGURED` 并阻止危险动作；拟合只有 PASS 才能导入。
- APPLY 需要两次独立确认，并提示成功后跨重启生效。
- 断线、超时或取消 mutating 命令后结果为未知，只允许 `CAL STATUS` 只读复核。
- UNDO 可操作但必须两次确认；DAC1/DAC2 未提供字段显示 `NOT_PROVIDED`。
- “会话导出”页显示通过 CRC 的解码点；错误 CRC 点不会进入表格。
